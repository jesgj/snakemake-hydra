snakemake-hydra Snakemake + Pixi modular NGS workflows

One entrypoint, four sequencing pipelines.

The project dispatches RNA-seq, WGBS, ChIP-seq/CUT&RUN, or ATAC-seq from a single `config/config.yaml` switch, then builds a selected workflow from reusable rule modules.

System At A Glance

This repository is a workflow application. Snakemake owns dependency resolution, Pixi owns the tool environment, and the workflow modules own pipeline behavior.

RNA-seq

Expression workflow

FastQC, fastp, Kallisto, HISAT2, duplicate metrics, BigWig output, optional gene body coverage, and MultiQC.

WGBS

Methylation workflow

FastQC, fastp, Bismark, deduplication, BAM filtering, MethylDackel M-bias/extraction, and MultiQC.

ChIP/CUT&RUN

Enrichment workflow

Bowtie2 alignment, BAM QC, filtering, deepTools plots, heatmaps, BigWigs, input subtraction, and MultiQC.

ATAC-seq

Accessibility workflow

Bowtie2, duplicate metrics, filtered BAMs, fragment QC, BigWigs, MACS3 or Genrich peak calling, and MultiQC.

Repository Structure

The top-level `Snakefile` only dispatches. Each selected workflow prepares config and samples, then imports the shared and pipeline-specific rule files it needs.

Snakefile Reads `config/config.yaml` and imports only the selected pipeline.
workflows/*.smk Validate config, normalize samples, define final targets, and include rules.
workflows/rules/**/*.smk Implement concrete Snakemake steps such as trimming, alignment, QC, and peak calling.
src/utils.py Discovers FASTQs and validates required config paths.
results/ and logs/ Receive pipeline outputs, tool reports, and `{log}.out` / `{log}.err` files.

Execution Model

Snakemake builds a DAG from declared inputs and outputs. The selected module decides what the final `rule all` requires.

Pipeline Dispatch

# config/config.yaml
pipeline: "wgbs"

# Snakefile imports rules as:
wgbs_fastqc_raw_pe
wgbs_bismark_alignment
wgbs_multiqc

Rule Composition

include: "rules/qc.smk"
include: "rules/trimming_and_qc.smk"
include: "rules/wgbs/alignment.smk"
include: "rules/wgbs/methyldackel.smk"
include: "rules/multiqc.smk"

Pipeline Routes

The routes share early QC and trimming patterns, then diverge into assay-specific alignment, processing, reporting, and final target outputs.

rnaseq

Expression quantification and alignment

Raw FastQC fastp Trim Kallisto Quant HISAT2 Align Duplicate Metrics BigWig + MultiQC
  • Requires paired-end samples.
  • Optional gene body coverage is controlled by `rnaseq.gene_body_coverage.enabled`.
  • Correlation heatmaps are generated only with at least two aligned BAMs.
wgbs

Bisulfite alignment and methylation extraction

Raw FastQC fastp Trim Bismark Align Deduplicate Filter + Sort MethylDackel + MultiQC
  • Requires paired-end samples.
  • Bismark creates `Bisulfite_Genome/` next to the configured reference genome.
  • Main methylation outputs include `_CpG.methylKit` and `_CpG.bedGraph`.
chip_cr

Protein-DNA enrichment and signal tracks

Raw FastQC fastp Trim Bowtie2 Align BAM QC + Filter deepTools BigWig Subtraction
  • Supports paired-end and single-end samples.
  • Signal samples named `_repN` pair with controls named `_input_repN`.
  • Heatmap generation excludes input-control samples.
atacseq

Chromatin accessibility and peak calling

Raw FastQC fastp Trim Bowtie2 Align Dedup + Filter Fragment QC MACS3/Genrich Peaks
  • Requires paired-end samples.
  • `peak_caller` must be `macs3` or `genrich`.
  • Both peak caller paths expose `peaks/_peaks.narrowPeak`.

Samples And Config

Samples can be declared explicitly or discovered from FASTQ names in `raw_fastqs_dir`. The selected workflow writes normalized sample data back into `config["samples_info"]`.

Manual declaration

samples_info:
  treatment_rep1:
    R1: "data/treatment_rep1_R1.fastq.gz"
    R2: "data/treatment_rep1_R2.fastq.gz"
    type: "PE"

Discovery patterns

Read Type Supported Names
Paired-end _R1/_R2, _1/_2, .R1/.R2
Single-end <sample>.fastq.gz or <sample>.fq.gz

Operating Commands

`pixi.toml` defines dependencies, but no tasks. Commands are run explicitly through `pixi run`.

Validate and run

# Install or update the environment
pixi install

# Dry-run the selected pipeline
pixi run snakemake -n --cores 1

# Execute the selected pipeline
pixi run snakemake --cores 8 --printshellcmds --latency-wait 60

Focused checks

# Dry-run through one imported rule
pixi run snakemake -n --cores 1 --until wgbs_multiqc

# Dry-run one concrete output
pixi run snakemake -n --cores 1 results/wgbs/methyldackel/sample_CpG.methylKit

# Print the DAG
pixi run snakemake --dag --cores 1

Where To Change Things

Add new user-facing config keys in the owning workflow, `config/config.yaml`, and `README.md`. Add executable behavior in rule files, keep shell commands running through `pixi run`, and verify with scoped Snakemake dry-runs for the active pipeline.
